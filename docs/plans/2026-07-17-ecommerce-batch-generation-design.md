# 电商批量生图设计

## 目标

把已经调好的 1～20 个动作队列保存为动作模板组。用户选择包含 20～100 套服装的根目录后，系统读取每套子目录中按 1～6 编号的实拍图，固定以“动作图 + 六张服装图”的 6+1 方式生成。每个动作先生成一张，质检不通过才重试，最多三张；三张都失败则进入人工复核，但整批继续。

## 关键约束

- 六张服装图必须完整保留，兼顾全身结构、半身构图和领口等特写细节。
- 任务必须写盘持久化，浏览器刷新和后端重启后能够恢复。
- 平台真实并发上限未知，不能假设无限；本地提供 1～20 的可调在途上限，默认 10。
- 提交与结果必须携带稳定 task id，平台乱序返回也要归回原服装、原动作。
- 每次状态变化原子写入 JSON，避免断电后整个批次损坏。
- 质检优先服装款式一致性；背景、道具和动作轻微差异不作为关键失败。

## 数据流

1. 从当前多图队列保存动作模板：每个有效队列保存图 1、提示词、平台、模型、比例和分辨率。
2. 扫描服装根目录：每个直接子目录是一套服装，按文件名开头的 1～6 识别六张参考图。
3. 为每套服装生成一次“服装真值档案”：领口、衣襟、盘扣、拉链、材质、花纹、关键位置关系和不确定项。
4. 展开任务矩阵：服装 × 动作。任务初始状态为 pending。
5. 调度器按服装分波：同一套服装的动作受在途上限保护并发执行，整波结束后才进入下一套；每次生成固定发送 6+1 张图。
6. 候选图进入视觉质检。通过则归档 accepted；不通过则把缺陷摘要加入下一次纠错提示词。
7. 三次不通过时写入 manual_review，并保存三张候选图及质检报告；调度器继续后续任务。

## 状态机

`pending → preparing → submitted → generating → qc → accepted`

失败分支：`qc_failed → retry_pending → ...`，达到三次后进入 `manual_review`。可恢复异常进入 `interrupted`，恢复时回到最近一个安全状态。批次支持 `draft/running/paused/completed/cancelled`。

## AI 质检

质检输入为六张服装实拍、服装真值档案和当前候选图。要求结构化 JSON 输出：总分、置信度、领口、衣襟、盘扣、拉链、材质、花纹分项，关键错误列表和结论。关键结构出现明确错误时直接失败；没有关键错误且总分达到阈值时通过。真实七图连通测试确认 `gpt-4.1` 当前在 HK 返回 503，因此默认使用已验证可接收七图并返回结构化 JSON 的 `gemini-2.5-pro`，界面仍允许修改。

视觉模型不能提供百分之百商品合规保证。人工复核目录和抽样复核必须保留，特别是盘扣数量、小花纹、遮挡位置和同色细节。

## 就地归档

每套服装原文件夹下创建 `AI换装结果-批次名` 子文件夹。通过的动作图直接放在该文件夹并以 `动作编号-动作名-OK` 命名；质检失败的候选图放进 `不匹配` 子文件夹并标注第几次。某个动作三张都失败时，三张候选和报告进入暂存目录；该套服装整波结束后，暂存目录改名为 `有N张需要人工补齐`。根目录同时写入 `批次质检记录.json`。

## 失败恢复

- API 429/5xx 使用指数退避，不把传输失败计入三次画质重试。
- 平台已有 request id 时只恢复轮询，禁止重复提交扣费。
- 单任务异常不终止批次。
- 每个接受结果和人工复核结果都使用服装名、动作序号和 attempt 编号命名。
