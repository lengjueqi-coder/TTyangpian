# ADR-0001：电商批量生图采用独立可恢复工作流

## 状态

已接受

## 背景

现有多图队列适合人工准备和抽卡，但 20～100 套服装乘以 1～20 个动作会形成数百到上千个长时间任务，并需要文件夹导入、按服装分波并发、渐进重试、AI 质检、人工复核、就地归档和重启恢复。

## 决策

新增独立的“电商批量生图”顶层板块，复用现有模型配置、图片上传和结果保存能力，但使用自己的动作模板、服装批次、持久化任务状态机和调度器。固定保留动作图加六张服装参考图的 6+1 输入。

## 结果

### 正面

- 手动多图队列保持简单，不被批处理状态污染。
- 批次可以暂停、恢复、追踪失败和继续后续任务。
- 后续可独立校准质检阈值和并发参数。

### 负面

- 需要维护一套额外的批次数据结构和界面。
- AI 质检会增加调用成本，并仍需人工复核兜底。

### 中性

- 第一版继续使用 JSON 原子写盘；数据量或多用户需求显著增长后再评估 SQLite，不提前引入数据库。

## 备选方案

- 继续扩展现有多图队列：实现快，但批次恢复、服装级统计和人工复核会与手动操作耦合，拒绝。
- 独立外部脚本监听文件夹：后台稳定，但用户看不到任务和失败原因，且重复配置模型，拒绝。
